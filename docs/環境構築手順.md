# 開発環境の準備と起動

この手順は、現在のリポジトリ構成に合わせた Windows 向けの案内です。依存ライブラリの更新やソースコードの変更は行いません。

## 必要なもの

| 用途 | 用意するもの | 確認方法 |
|---|---|---|
| バックエンド | JDK 21、sbt ランチャー | `java -version`、`sbt --version` |
| フロントエンド | Node.js 24 LTS と npm | `node --version`、`npm --version` |
| DB用SQLの実行（任意） | PostgreSQL と `psql` | `psql --version` |

Play 3 は Java 11、17、21 をサポートしています。このプロジェクトでは JDK 21 を使うと環境をそろえやすくなります。sbt のプロジェクト版は `studio-backend/project/build.properties` で 1.11.6 に固定されています。Node.js の対応条件は `studio-frontend/package.json` にあり、Node.js 24 LTS を推奨します。

- [Play Framework 3 の必要環境](https://www.playframework.com/documentation/3.0.x/Requirements)
- [Windowsでのsbt導入手順](https://www.scala-sbt.org/1.x/docs/Installing-sbt-on-Windows.html)
- [Node.jsのリリース状況](https://nodejs.org/en/about/previous-releases)

## 初回準備

リポジトリのルートで次を実行し、フロントエンドの依存関係をロックファイルに沿ってそろえます。

```powershell
Set-Location .\studio-frontend
npm ci
```

バックエンドは `sbt` が依存ライブラリを取得します。初回起動時は少し時間がかかることがあります。

## 起動

バックエンドとフロントエンドを、それぞれ別のターミナルで起動します。

ターミナル1:

```powershell
Set-Location .\studio-backend
sbt run
```

ターミナル2:

```powershell
Set-Location .\studio-frontend
npm run dev
```

- 画面: <http://localhost:5173>
- API疎通確認: <http://localhost:9000/api/ping>

Vite は `/api` への通信を `http://localhost:9000` に転送します。ブラウザーの画面から API を呼び出すには、バックエンドとフロントエンドの両方を起動してください。

## 既存の確認コマンド

```powershell
# studio-frontend で実行
npm run build

# studio-backend で実行
sbt test
```

現在、フロントエンドの `package.json` にはビルド以外の型検査・静的解析スクリプトはありません。

## DB用SQL（必要な場合のみ）

現在のバックエンドはメモリ上のリポジトリを使っており、`DB/script/CREATE_TABLE/` のSQLとは接続されていません。通常の画面開発では PostgreSQL の準備は不要です。アプリケーションを再起動すると、メモリ上の予約データは失われます。

SQLを試す場合は、PostgreSQL と `psql` を用意し、リポジトリのルートで環境変数を設定してから、使い捨ての開発用DBを対象に実行してください。次のスクリプトはフォルダー内のSQLを名前順にすべて実行します。

```powershell
$env:DB_HOST = "localhost"
$env:DB_PORT = "5432"
$env:DB_NAME = "music_studio_dev"
$env:DB_USER = "postgres"

.\DB\script\CREATE_TABLE\run_create_tables.ps1
```

パスワード認証が必要なら、実行前に同じ PowerShell セッションで `$env:DB_PASSWORD` を設定してください。

## 現在のビルド定義

バックエンドでは sbt の `build.sbt` と `project/plugins.sbt` を使います。`build.sc` には Mill 用の別定義があり、Scala の版が sbt 定義と異なります。正式な使い分けが決まるまでは、この手順の sbt コマンドを使ってください。
