## 2. 列挙値（Enums）

### 2.1 予約状態（BookingStatus）

| 日本語 | 英語 | 意味 |
|---|---|---|
| 予約確定 | Confirmed | 予約が確定した状態。作成時即確定という旧定義は[Issue23の回答](https://github.com/cardamon04/music-studio-reservation/issues/23#issuecomment-5972740105)で変更された。全員承認との状態遷移・引当時点は確認中。利用開始・終了は別に記録する。 |
| 予約キャンセル | Canceled | 取消された状態（理由は別途 CancellationReason で管理）。 |

### 2.2 スタジオ枠状態（StudioSlotStatus） ※表示用

| 日本語 | 英語 | 意味 |
|---|---|---|
| 空 | Empty | 有効な予約が存在しない。 |
| 予約確定 | Confirmed | 確定予約があり、「使用中」「利用終了」の条件に当てはまらない。未Check-inなら開始時刻後も維持する。 |
| 使用中 | InUse | `BookingStatus=Confirmed` かつ現在時刻が枠内、Check-in済み・未Check-out。学生予約は**メンバー全員確認必須**。 |
| 利用終了 | CheckedOut | `BookingStatus=Confirmed` かつTAによるCheck-out済み。早期退室でも元の予約枠全体を維持し、再予約不可。 |
| 予約キャンセル | Canceled | 取消済みの履歴表示。空き枠の判定では有効な予約として扱わない。 |

APIでは確定した英語の列挙値を返し、画面で日本語に対応させる。承認待ちの状態・列挙値は確認中で、現行コードの`Reserved`を承認待ちと読み替えない。現行の`Completed`はカレンダーで`InUse`（使用中）へ変換されており、メンバー承認の完了には流用しない。取消の表記は`Canceled`に統一する。`CheckedOut`は枠の表示用であり、予約状態ではない。予定終了時刻の経過だけではCheck-out済みとしない。

## 4. ドメインイベント

| Event (EN) | 日本語概要 | 主なペイロード |
|---|---|---|
| BookingConfirmed | 予約が確定した | bookingId, studioId, usageDate, timeSlot, reservationType, occurredAt |
| BookingCanceled | 予約が取消された | bookingId, reason（例: 無断キャンセル）, performedBy（TAId 任意）, occurredAt |
| EquipmentAllocated | 備品が引当られた | bookingId, equipmentId, quantity, occurredAt |
| EquipmentAllocationReleased | 引当が解放された | bookingId, equipmentId, quantity, occurredAt |
| EquipmentCheckedOut | 備品が貸し出された | bookingId, equipmentId, quantity, performedBy, occurredAt |
| EquipmentReturned | 備品が返却された | bookingId, equipmentId, quantity, performedBy, occurredAt |
| BookingCheckedIn | スタジオ利用を開始した | bookingId, performedBy（TAId）, occurredAt |
| BookingCheckedOut | スタジオ利用を終了した | bookingId, performedBy（TAId）, occurredAt |
| AllMembersVerified | 学生予約のメンバー全員の本人確認が完了した | bookingId, verifiedMemberNumbers[], verifiedBy（TAId）, verifiedAt |
| BookingGraceExpired | 予約開始10分の猶予が経過した（表示/通知用） | bookingId, graceMinutes=10, occurredAt |

受付業務一式は最初の開発範囲に含む。通信契約は[API詳細設計書の受付業務](API詳細設計書.md#reception-api)を参照する。更新操作の `performedBy` は認証されたTAId、`operationId` は同じ操作の再送を識別するUUIDとする。本人確認の記録では実行者・日時を `verifiedBy / verifiedAt` として保持する。TAによる取消では `BookingCanceled.performedBy` は必須。

備品の数量項目は `reservedQuantity`（予約数量）、`checkedOutQuantity`（累計貸出数量）、`returnedQuantity`（累計返却数量）とする。スタジオのCheck-outは利用終了、備品のCheckoutは貸出を表し、それぞれ別の記録とする。

## 5. ポリシー/不変条件（抜粋）

- **重複禁止**：同一 `Studio × UsageDate` で **TimeSlotの実時間レンジが重なる** 予約は同時に存在できない。  
  - FullDay は当日の全Periodに重なる。HalfDay は DayHalfMapping に定義されたPeriod群に重なる。  
- **1コマ1組**：同一スタジオ・利用日・限（Period）は1組だけが利用する。早期Check-outで残り時間を開放せず、元の予約時間枠全体を重複判定の対象にする。半日・終日は含まれる各限に適用する。
- **予約期間制限**：日本時間（`Asia/Tokyo`）で **今日から7日後まで（両端を含む）** のみ予約可能。過去の日付および8日後以降の日付は予約不可。
- **学生予約のCheck-in条件**：**メンバー全員が揃い、学生証提示をTAが確認**（AllMembersVerified）。自動Check-inは対象外。  
- **キャンセル締切**：利用者都合の取消は前日 23:59（Asia/Tokyo）まで可。開始10分経過は自動取消せず、UIで表示する。**TAによる無断キャンセル理由の取消は当日も可能**。
- **優先度**：`授業 > イベント > 学生`（自動奪取は行わない／同時受付時の指針）。

## 6. 表記ルール（日本語↔英語）

- 予約＝Booking／予約番号＝BookingId／予約状態＝BookingStatus／スタジオ枠状態＝StudioSlotStatus／予約枠＝Slot  
- 学生＝Student／学生番号＝StudentNumber／メンバー＝Members／講師＝Instructor／TA＝TeachingAssistant  
- 限＝Period／半日区分＝DayHalf（AM/PM）／時間枠＝TimeSlot（Period/HalfDay/FullDay）  
- 備品＝EquipmentItem／在庫＝Stock／引当＝Allocation／貸出＝Checkout／返却＝Return  
- 取消理由＝CancellationReason（**無断キャンセル**／利用者都合 など）

| 論理名・登録状態 | 意味・文脈とルール | 物理名・似た語との差・未決事項 |
|---|---|---|
| メンバー承認（暫定登録。全員承認が必要なことは確認済み） | 予約メンバーが予約内容に同意すること。A・Bの予約でAだけが同意しても全員承認ではない。対象外のCの承認をBの代わりに数えない | 承認結果の照合は`BookingMemberApprovals`。学生証提示を確認する`IdentityVerification`と別。作成者の初期承認、期限、拒否、変更後の再承認は質問中 |
| 全員承認（暫定登録。集合一致の判定は確認済み） | 学生予約の対象メンバーは1名以上。承認済みメンバーが対象の部分集合で、全員一致したときに満たす条件 | `allMembersApproved`。この真偽だけでは、枠・在庫条件を含めた予約確定やCheck-in成功を意味しない |
